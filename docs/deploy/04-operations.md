# Эксплуатация: бэкапы, мониторинг, обновления

[← к оглавлению деплоя](../DEPLOY.md)

## Резервное копирование

- **PostgreSQL** — ежедневный `pg_dump` (или `pg_basebackup` для полных бэкапов) в
  отдельное хранилище (S3-совместимое, не тот же VPS) — job/cron вне кластера, хранение
  минимум 14 дней. Это особенно критично для self-hosted БД на одиночном VPS (Вариант A/B
  из [`03-vps-guide.md`](./03-vps-guide.md)), где нет managed-репликации.
- **Media (S3/MinIO)** — версионирование бакета или отдельная политика снапшотов на
  стороне хранилища.
- Перед любым ручным вмешательством в БД (хотфикс, разбор спора вручную) — снапшот перед
  изменением.
- Раз в квартал — тестовое восстановление бэкапа на staging, чтобы бэкап был не
  теоретическим.

## Миграции в проде

Миграции — только как отдельный одноразовый шаг перед раскаткой новой версии кода
(`Job`/Helm-хук в k8s, `docker compose run --rm api php artisan migrate --force` в
Compose), никогда не как часть старта обычного пода/контейнера — иначе несколько реплик
`api`, поднимающихся одновременно, могут гонять миграцию параллельно.

## Мониторинг и логи

- **Laravel Horizon** — дашборд состояния очередей (вебхуки ЮKassa, уведомления,
  авто-подтверждение сделок) — доступен по защищённому пути, не публично.
- Структурные логи (`json`-формат) из всех контейнеров собираются в общий стек логов; на
  минимальной конфигурации VPS достаточно `kubectl logs`/`docker compose logs` + ротация,
  на проде — агрегатор (Loki/ELK) по мере роста.
- Health-check `/api/health` — используется и Kubernetes-пробами, и внешним
  uptime-мониторингом (пинг раз в минуту).
- Отдельный алерт на: очередь Horizon растёт быстрее, чем обрабатывается (риск не
  обработать вебхук оплаты вовремя), и на рост `payouts.status = failed`
  (см. [`../database/05-marketplace-payment.md`](../database/05-marketplace-payment.md)).

## Обновления и откат

- k8s (Вариант A): `helm upgrade` делает rolling update `api`/`frontend`/`websocket` без
  простоя (readiness-проба не пускает трафик на под, пока он не готов); откат —
  `helm rollback animalfriendly <revision>`.
- Docker Compose (Вариант B): обновление пересобирает и перезапускает контейнеры с
  кратковременным простоем `api` (если нужен zero-downtime — переходить на Вариант A);
  откат — `git checkout <previous-tag> && docker compose up -d --build`.
- Миграции, ломающие обратную совместимость (переименование/удаление колонки, на которую
  ещё смотрит предыдущая версия кода) — только в два релиза (add → deploy → backfill →
  следующий релиз убирает старое), чтобы rolling update не уронил старые поды посреди
  раскатки.
