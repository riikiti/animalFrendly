# Соглашения по БД

[← к оглавлению БД](../DATABASE.md)

- **PostgreSQL 16**, кодировка `UTF8`.
- **Первичные ключи:** `ULID` (строка, сортируется по времени) для сущностей, доступных
  через публичный API (пользователи, питомцы, листинги, сделки) — не даёт угадывать
  соседние id и не палит объём таблицы. Для чисто внутренних связующих/логовых таблиц
  допустим `bigint identity`.
- **Деньги:** всегда целые **минорные единицы (копейки)**, колонка `*_amount` типа
  `bigint`, никогда `float/decimal` с плавающей семантикой в коде — конвертация в рубли
  только на слое отображения. Соответствует `Shared\Domain\ValueObjects\Money` из
  [`../plan/04-backend-structure.md`](../plan/04-backend-structure.md).
- **Время:** все `timestamp` в UTC (`timestamptz`), конвертация в локальную зону — на
  фронтенде/мобильном.
- **Мягкое удаление:** `deleted_at` — только там, где нужна история/восстановление
  (пользователи, листинги, сделки, приюты). Справочники (`species`, `breeds`,
  `subscription_plans`) не удаляются физически — деактивируются флагом `is_active`.
- **Аудит статусов:** любая сущность со state machine (`orders`, `adoption_requests`)
  обязана иметь таблицу истории статусов (`*_status_history`), а не только текущее поле.
- **Именование:** таблицы — `snake_case`, множественное число; внешние ключи —
  `<entity>_id`; enum-подобные поля — через Postgres `enum`-тип или `varchar` + CHECK
  constraint (не «магические» числа).
- **Миграции:** одна миграция = одно осмысленное изменение, префикс имени файла —
  название модуля-владельца таблицы (`..._identity_create_users_table.php`), см.
  [`../plan/04-backend-structure.md`](../plan/04-backend-structure.md).
