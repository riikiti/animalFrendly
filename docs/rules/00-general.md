# Общие правила

[← к оглавлению правил](../RULES.md)

## Главное правило: план → код

Любое изменение скоупа, доменной модели, структуры папок, стека или бизнес-правил
(например, размер комиссии, срок эскроу, лимиты подписки) сначала вносится в
соответствующий файл `docs/plan/*.md` или `docs/database/*.md`, и только потом
реализуется в коде. PR, меняющий поведение без синхронной правки плана — не принимается.
Если реализация неизбежно разошлась с планом (нашли более удачный вариант по ходу
разработки) — план поправить в том же PR.

## Секреты и конфигурация

- Все ключи/URL/секреты сторонних сервисов (ЮKassa, FCM, S3, SMTP, Meilisearch, Reverb) —
  только в `.env`, никогда не хардкодятся и не коммитятся.
- `.env.example` поддерживается в актуальном состоянии при добавлении новой переменной.
- В backend-коде `env()` вызывается **только** внутри файлов `config/*.php`; в остальном
  коде — исключительно `config('yookassa.secret_key')` и т.п. Это даёт кэшируемость
  конфига (`config:cache`) и единую точку правды.
- Во frontend/mobile — переменные окружения на этапе сборки (`import.meta.env.*` /
  `BuildConfig`), секреты бэкенда никогда не попадают в клиентский код (только публичные
  ключи, например publishable-ключ ЮKassa для виджета оплаты, если используется).

## Git и ревью

- Ветки: `main` — стабильная, `feature/<module>-<short-description>`. PR обязателен,
  прямые пуши в `main` запрещены.
- Коммиты в формате Conventional Commits (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`)
  с указанием модуля: `feat(marketplace): add escrow auto-confirm job`.
- PR не мержится без: прохождения тестов, статического анализа/линта, актуализации
  плана (если применимо), и если PR добавляет таблицу — обновления `docs/database/*.md`.

## Безопасность

- Валидация всех входных данных на границе системы (HTTP-запросы, вебхуки) — никогда не
  доверять клиенту.
- Авторизация проверяется явно на каждом эндпоинте (Policy/Gate на backend), не
  подразумевается по факту наличия токена.
- Любые операции с деньгами и статусами сделок — идемпотентны и логируются
  (`order_status_history`, `audit_logs`), см. [`04-payments-escrow.md`](./04-payments-escrow.md).

## Единый источник дизайна

- Дизайн-токены (цвета, отступы, типографика, радиусы) определяются один раз
  (`frontend/src/shared/ui/tokens`) и переносятся 1:1 в мобильное приложение
  (`androidApp/ui/theme`). Изменение токена — правка в обоих местах в одном PR,
  расхождение дизайна сайта и приложения — баг.
