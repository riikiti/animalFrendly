# Инфраструктура и деплой

[← к оглавлению правил](../RULES.md) · план — [`../plan/12-infrastructure.md`](../plan/12-infrastructure.md) · гайды — [`../DEPLOY.md`](../DEPLOY.md)

- **Единый бэкенд/БД:** мобильное приложение и фронтенд обращаются только к общему REST/
  WebSocket API — никаких прямых подключений к БД из клиента, никакой отдельной «мобильной»
  копии бизнес-логики. Обоснование — [`../plan/03-architecture.md`](../plan/03-architecture.md).
- **Один образ — несколько ролей:** `api`, `queue-worker`, `scheduler`, `websocket`
  собираются из одного `backend/Dockerfile`, различается только команда запуска
  (`CONTAINER_ROLE`). Не создавать отдельные Dockerfile под каждую роль.
- **Секреты — никогда в образе и никогда в git.** Только через k8s `Secret` / `.env`,
  подключаемый на этапе запуска контейнера. Полный список —
  [`../plan/10-integrations.md`](../plan/10-integrations.md).
- **Миграции — отдельный одноразовый шаг** перед раскаткой новой версии (Helm-хук `Job` /
  `docker compose run --rm api artisan migrate --force`), никогда не запускаются при старте
  обычного пода — иначе параллельные реплики гоняют миграцию одновременно.
- **Обратно совместимые миграции:** ломающее изменение схемы (переименование/удаление
  колонки) выкатывается минимум в два релиза (добавить → задеплоить → перелить данные →
  только в следующем релизе убрать старое), чтобы rolling update не уронил ещё не
  обновлённые поды.
- **Kubernetes — приоритет**, Docker Compose — для локальной разработки и как fallback для
  небольших VPS-инсталляций (через k3s, см. [`../deploy/03-vps-guide.md`](../deploy/03-vps-guide.md)).
  Новая инфраструктурная фича сначала описывается в `docs/plan/12-infrastructure.md` /
  `docs/deploy/*.md`, потом реализуется в манифестах — то же правило «план → код», что и
  для остального кода (см. [`00-general.md`](./00-general.md)).
- **CI/CD — после основного кода.** Полноценный пайплайн (тесты + линтеры + сборка + деплой,
  [`../deploy/05-cicd.md`](../deploy/05-cicd.md)) настраивается, когда есть работающий код
  модулей фаз 1–6 — не строится заранее ради пустых модулей. До этого момента тесты и
  линтеры (см. [`05-testing.md`](./05-testing.md)) — обязательная локальная практика перед
  каждым PR, даже без автоматизации в CI.
- **Деплой в production — только с подтверждением** (GitHub Environment с required
  reviewer), деплой в staging — автоматический на каждый мердж в `main`.
- **Health-check `/api/health`** обязателен у `api` — на нём завязаны k8s-пробы и внешний
  uptime-мониторинг; удаление или изменение контракта эндпоинта — ломающее изменение.
- **Логи — только stdout/stderr**, сбор и хранение — задача инфраструктуры (Grafana Loki +
  Promtail, см. [`../deploy/06-logging.md`](../deploy/06-logging.md)), не приложения;
  приложение никогда не пишет логи в файл контейнера. Формат и что нельзя логировать —
  [`../plan/13-logging.md`](../plan/13-logging.md).
