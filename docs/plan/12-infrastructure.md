## Приоритет оркестрации

1. **Kubernetes — приоритетная целевая платформа.** Прод и staging разворачиваются как
   набор манифестов/Helm-chart'ов, промышленные окружения (масштабирование API, воркеров
   очередей, скользящие обновления, автоскейлинг) рассчитаны в первую очередь на k8s.
2. **Docker Compose — для локальной разработки и как fallback** для маленьких инсталляций
   (например, один VPS без кластера). Все Dockerfile'ы одинаковы что для Compose, что для
   k8s — разница только в способе оркестрации, не в образах.
3. На «голом» VPS без готового k8s-кластера рекомендуется **k3s** (лёгкий однонодовый
   Kubernetes) — так прод-манифесты остаются одними и теми же независимо от того, VPS это
   или облачный кластер. Подробности — [`../deploy/03-vps-guide.md`](../deploy/03-vps-guide.md).

## Сервисы (контейнеры)

| Сервис | Образ | Реплики (прод) | Примечание |
|---|---|---|---|
| `api` | `backend/Dockerfile` (PHP-FPM + nginx или Octane) | 2+ | stateless, HPA по CPU/RPS |
| `queue-worker` | тот же образ, другая команда (`horizon`) | 1-2 | обработка вебхуков ЮKassa, уведомлений, авто-подтверждения |
| `scheduler` | тот же образ, `php artisan schedule:run` | CronJob (k8s) / cron-контейнер (Compose) | раз в минуту запускает `deals:auto-confirm` и др. |
| `websocket` | `backend/Dockerfile` (Reverb) | 1-2 | реалтайм-чат, sticky-сессии на Ingress |
| `frontend` | `frontend/Dockerfile` (Vite build → статика за nginx) | 2+ | stateless, отдаётся через CDN/Ingress |
| `postgres` | управляемая БД облака **или** `StatefulSet` + PVC | 1 (+ реплика для отказоустойчивости в проде) | см. правило миграций — `deploy/04-operations.md` |
| `redis` | управляемый Redis **или** `StatefulSet` | 1 | кэш, очереди, presence |
| `meilisearch` | официальный образ | 1 | индекс поиска, восстанавливается из БД при потере |
| `minio` (если не внешний S3) | официальный образ | 1 (+ реплики в режиме distributed при росте) | либо использовать облачный S3-совместимый сервис вместо самохоста |

Полный список образов и что в них — [`../deploy/01-containers.md`](../deploy/01-containers.md).
Структура k8s-манифестов — [`../deploy/02-kubernetes.md`](../deploy/02-kubernetes.md).

## Общие принципы

- Один и тот же образ `api` используется для `api`, `queue-worker`, `scheduler` и
  `websocket` — отличается только команда запуска контейнера, не сборка. Меньше
  расхождений между окружениями.
- Секреты (ЮKassa, FCM, БД, S3) — только через `Secret` в k8s / `.env`, подключаемый в
  Docker Compose как `env_file`; ни один секрет не попадает в образ на этапе сборки.
- Миграции БД выполняются как отдельный одноразовый шаг перед раскаткой новой версии
  (`Job` в k8s / `docker compose run --rm api php artisan migrate --force`), не при старте
  каждого пода — иначе параллельные поды гоняют миграции одновременно.
- Health-check эндпоинт (`/api/health`) обязателен у `api` для readiness/liveness проб.
